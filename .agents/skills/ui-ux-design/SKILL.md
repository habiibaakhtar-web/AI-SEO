# UI/UX Design

- Start from the user's goal, primary action, content priority, and likely failure states. Preserve established product conventions unless a redesign is requested.
- Inspect existing shadcn components and layout patterns before adding markup. Prefer composition over creating another one-off primitive.
- Make hierarchy legible through type, spacing, grouping, and contrast. Keep repeated controls predictable and actions close to the objects they affect.
- Cover loading, empty, error, disabled, success, destructive, and permission-limited states when relevant.
- Use Lucide icons consistently and pair unfamiliar icon-only controls with accessible labels or tooltips.
- Consider Aceternity UI or Magic UI only when a deliberate expressive effect materially improves the page. Preview registry code and dependencies before adding it; adapt it to the existing design language.
- Avoid generic template styling, gratuitous gradients, excessive cards, and animation that competes with task completion.
- Validate the result at representative desktop and mobile sizes and preserve keyboard and reduced-motion behavior.
